Does the estimator actually work?

We check it the only honest way: feed it synthetic data with a known maintenance calories (TDEE) and see how close it gets — across easy and hard conditions, weak spots included. Every number here comes from a real run of the real estimator; nothing is hand-picked.

How the check works

  1. Pick a hidden true TDEE and a calorie deficit.
  2. Simulate a daily weight/intake log from it via the energy-balance model, then corrupt it with realistic water-weight noise, refeed spikes and missing days — the same confounders that swamp fat loss in real life.
  3. Hand only the noisy, gappy log to the estimator (never the truth).
  4. Compare its recovered TDEE to the hidden true TDEE.

Why this isn't circular

Known limitations (stated plainly)

  • The confidence interval is likely optimistic. It's an ordinary least-squares interval fit on an already-smoothed weight series, which understates the true uncertainty — read it as indicative, not exact.
  • The 7,700 kcal/kg conversion is a population average. Real weight change mixes fat, lean tissue and water, so an individual's figure can differ (see the mismatch section above for the resulting, predictable bias).
  • Accuracy degrades on sparse, noisy input. The "sparse & noisy" scenario above is the honest weak spot: with heavy noise, frequent gaps and a short window, some estimates miss the stated tolerance. That's why the app withholds a number until it has enough consistent data.
